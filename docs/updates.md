# Обновления и номера сборок

Публичная версия приложения остаётся **1.0** (`AssemblyVersion` и `AssemblyFileVersion` — `1.0.0.0`). Отдельный номер `Updates.CurrentBuild` различает исправления внутри этой версии. Он записывается в EXE как `AssemblyInformationalVersion`, например `1.0.0+build.1`, и не меняет привычное название версии в интерфейсе.

Номер сборки увеличивается перед выпуском нового набора изменений, а не при каждом запуске компилятора. Уже опубликованный номер нельзя повторно использовать для другого кода. Номер не выводится из даты загрузки: повторная публикация старого архива не должна превращать его в обновление.

## Подготовка выпуска

1. Для очередной отдельной сборки увеличьте `CurrentBuild` в `src/Updates.cs`; сохраните номер продукта, если новый выпуск продукта не планируется.
2. Выполните `build.ps1`, `test.ps1` и `package.ps1`. Упаковка проверяет совпадение версии и номера сборки в исходнике и EXE.
3. Вместе с ZIP и `SHA256SUMS.txt` упаковка создаёт `release-build.txt`. Добавьте его содержимое в описание **того же** релиза GitHub и загрузите ZIP из этой же папки. Это HTML-комментарий, который GitHub не показывает читателю. Не редактируйте контрольную сумму вручную.
4. При замене разрешённого к обновлению релиза заменяйте и архив, и комментарий. На время несовпадения метаданных приложение сообщает о незавершённой публикации и не предлагает загрузку.

Само выполнение этих команд не публикует релиз. Публикация и замена существующих файлов выполняются отдельно в рамках согласованного выпуска.

## Сравнение

Приложение сначала сравнивает версии продукта, затем номера сборок одинаковой версии. Более новая сборка 1.0 предлагается как обновление; более старая не предлагается к загрузке. Совпадение версии без номера сборки не считается подтверждением актуальности. Для старого релиза без служебного комментария отображается сообщение о недоступном сравнении; страница релизов остаётся доступна по ссылке.

Комментарий привязан к SHA-256 конкретного ZIP из ответа GitHub. Дубли, повреждённый номер или несовпадающая сумма отклоняются. Служебный комментарий удаляется перед показом описания изменений в приложении. Адрес репозитория, имя архива, HTTPS-перенаправления, размер и SHA-256 скачанных данных по-прежнему проверяются.

Первую сборку с этой логикой необходимо установить вручную: прежняя версия приложения не умеет сравнивать внутренние номера сборок.
